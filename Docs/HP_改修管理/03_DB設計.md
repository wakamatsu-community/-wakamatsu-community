# データベース設計書（Cloud Firestore）

## 1. データベース概要

本システムでは、Google Cloud / Firebase の **Cloud Firestore**（Sparkプラン・無料枠）を正本データベースとして採用する。  
バイナリファイル（写真原本、PDF資料）は Google Drive（無料15GB）に保管し（Firebase Storageはクレジットカード登録不要運用の観点から不採用）、Firestore 側には参照情報（Drive File ID、URL、サムネイルURL）とメタデータを格納する。

---

## 2. コレクション一覧

| コレクション名 | 用途・管理内容 | ドキュメントID規則 | 主要クエリ・インデックス |
| :--- | :--- | :--- | :--- |
| **`events`** | 町内会公式行事・定例予定 | 自動生成 または `event_{YYYYMMDD}_{連番}` | `start ASC`, `category ASC` |
| **`communityEvents`** | 会員企画イベント（承認制） | 自動生成 | `status ASC, start ASC` |
| **`communityEvents/{id}/entries`** | イベント参加者台帳（サブコレクション） | 自動生成 | `createdAt ASC` |
| **`equipmentMaster`** | 備品マスタ（在庫数・保管場所・条件） | 備品キー (`tent`, `table`, `chair`, `generator`, `mower`) | 単一ドキュメント参照 |
| **`equipmentReservations`** | 備品予約台帳・貸出返納状況 | 自動生成 または `res_{YYYYMMDD}_{連番}` | `equipmentId ASC, startDate ASC` |
| **`opinions`** | 掲示板・意見交換・地域相談 | 自動生成 | `createdAt DESC`, `isPublic ASC` |
| **`documents`** | 回覧板・総会資料・会則・議事録メタデータ | 自動生成 | `year DESC, date DESC, category ASC` |
| **`photos`** | 写真アルバムメタデータ | 自動生成 | `status ASC, createdAt DESC, albumId ASC` |
| **`users`** | 会員プロファイル・役員ロール管理 | Firebase Auth の `uid` | 単一ドキュメント参照 |

## 4. 備品予約の Firestore トランザクション排他制御ロジック

複数会員が同一備品を同時予約した場合に在庫超過を防ぐため、Firestore の `runTransaction` を適用する。

```javascript
import { runTransaction, doc, collection, query, where, getDocs } from "firebase/firestore";

export async function reserveEquipmentWithTransaction(db, reservationData) {
    const { equipmentId, quantity, startDate, endDate } = reservationData;
    const masterRef = doc(db, "equipmentMaster", equipmentId);

    return await runTransaction(db, async (transaction) => {
        // 1. マスタから総在庫数を取得
        const masterSnap = await transaction.get(masterRef);
        if (!masterSnap.exists()) {
            throw new Error("指定された備品が存在しません。");
        }
        const totalStock = masterSnap.data().stock || 0;

        // 2. 期間重複の可能性のある有効予約を照会
        //    (ステータスが requested, approved, borrowed のもの)
        const reservationsRef = collection(db, "equipmentReservations");
        const overlapQuery = query(
            reservationsRef,
            where("equipmentId", "==", equipmentId),
            where("status", "in", ["requested", "approved", "borrowed"]),
            where("startDate", "<=", endDate)
        );
        const overlapSnap = await getDocs(overlapQuery);

        // 3. 貸出期間内の各日について日別使用数を計算
        const dailyUsage = {};
        overlapSnap.forEach((docSnap) => {
            const res = docSnap.data();
            // 返納日が貸出開始日以降のもののみ有効に重複判定
            if (res.endDate >= startDate) {
                let curr = new Date(Math.max(new Date(res.startDate), new Date(startDate)));
                const last = new Date(Math.min(new Date(res.endDate), new Date(endDate)));
                while (curr <= last) {
                    const dStr = curr.toISOString().slice(0, 10);
                    dailyUsage[dStr] = (dailyUsage[dStr] || 0) + (res.quantity || 1);
                    curr.setDate(curr.getDate() + 1);
                }
            }
        });

        // 4. 今回予約数量を加算して在庫チェック
        let checkCurr = new Date(startDate);
        const checkEnd = new Date(endDate);
        while (checkCurr <= checkEnd) {
            const dStr = checkCurr.toISOString().slice(0, 10);
            const planned = (dailyUsage[dStr] || 0) + quantity;
            if (planned > totalStock) {
                const remaining = Math.max(0, totalStock - (dailyUsage[dStr] || 0));
                throw new Error(`${dStr} の空き数量が不足しています（希望: ${quantity}台 / 残り: ${remaining}台）。`);
            }
            checkCurr.setDate(checkCurr.getDate() + 1);
        }

        // 5. アトミックに予約ドキュメントを作成
        const newResRef = doc(collection(db, "equipmentReservations"));
        transaction.set(newResRef, {
            ...reservationData,
            status: "requested",
            createdAt: new Date(),
            updatedAt: new Date()
        });

        return newResRef.id;
    });
}
```

## 5. 必要なFirestore複合インデックス定義

Firestoreで複数の `where` 条件および `orderBy` を組み合わせてクエリする際、事前に Firebase Console または `firestore.indexes.json` で作成が必要な複合インデックス一覧：

| 対象コレクション | 構成フィールド 1 | 構成フィールド 2 | 構成フィールド 3 | 用途・クエリ |
| :--- | :--- | :--- | :--- | :--- |
| **`equipmentReservations`** | `equipmentId` (昇順) | `status` (昇順) | `startDate` (昇順) | 備品・ステータス別の期間重複チェッククエリ |
| **`communityEvents`** | `status` (昇順) | `start` (昇順) | - | 承認済み企画イベントの開始日順一覧取得 |
| **`opinions`** | `isPublic` (昇順) | `createdAt` (降順) | - | 全体公開意見の新着順表示 |
| **`documents`** | `category` (昇順) | `date` (降順) | - | カテゴリ別資料の最新順表示 |
| **`photos`** | `status` (昇順) | `createdAt` (降順) | - | 承認済み写真の新着順表示 |
